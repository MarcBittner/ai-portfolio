# attack-surface — Code Review

## Summary
`attack-surface` is a small, well-factored passive attack-surface scanner: CT-log subdomain enumeration, deterministic exposure findings pre-mapped to SOC 2 / ISO 27001 (with a NIST/CMMC crosswalk), a severity-weighted posture score, and an LLM-written executive narrative riding on top of fully deterministic evidence. The architecture is clean — the LLM never invents findings or scores, and an offline fallback keeps every path runnable with zero keys. The code is in good shape (`ruff check` passes clean), but there is one correctness bug in live-mode hostname matching and a cluster of stale "live mode returns no findings" copy that now contradicts the shipped behavior.

## Architecture notes
- Clear separation: `ct.py` (enumeration) → `fingerprint.py` (findings) → `controls.py` (control roll-up) → `scanner.py` (orchestration + posture) → `narrative.py` (LLM prose) → `api.py` (transport). Findings carry their control ids inline, so the control roll-up in `controls.evaluate` is purely derived — the invariant "every failing control traces back to findings" holds by construction (`controls.py:36-49`).
- Two modes share one report shape. Fixture mode runs full fingerprint-driven findings on the owned synthetic domain (`scanner.py:36-66`); live mode derives findings *only* from public CT data via `fingerprint.derive_passive` (`scanner.py:93-117`). No active probing of third-party hosts exists at all — a sound responsible default.
- `llm.py` is a self-contained stdlib-only router (paid → local → free → offline) with a deterministic terminal fallback; `narrative.generate` also supports a browser→host Ollama path via `client_narrative` (`narrative.py:170-178`). Telemetry (provider, latency, cost, fallbacks) is threaded through cleanly.
- Posture scoring (`scanner.py:21-33`) deliberately caps low/medium *total* contribution (`min(n["medium"]*3, 24) + min(n["low"]*1, 12)`) so a large domain's volume of low-severity CT observations can't floor the grade while criticals/highs stay linear. **Verified sound**: on the fixture (2 critical, 2 high, 3 medium, 2 low) penalty = 20 + 12 + 9 + 2 = 43, score 57, grade D — caps not yet engaged, criticals/highs dominate. The cap only clamps once medium ≥ 8 or low ≥ 12, exactly the volume-not-security case it documents.

Live-mode CT severities are appropriately conservative: `CT_SENSITIVE_HOST` and `CT_NONPROD_HOST` are `low`, and `CT_SURFACE_SPRAWL` is `low` (`medium` only at ≥120 hosts) (`fingerprint.py:47,55,64-65`). The UI frames live results as passive intelligence, not a graded verdict, and shows neutral surface stats (`static/index.html:639-657`). This is the correct calibration — a hostname appearing in CT is by design, not a vulnerability. No change needed.

## Test coverage
- Solid unit coverage of the deterministic core: fingerprint rules (`test_fingerprint.py`), control roll-up and the orphan-evidence invariants (`test_controls.py`, `test_scanner.py:21-28`), posture before/after remediation with explicit grade transitions D→B (`test_narrative.py:46-58`), and narrative coverage of every critical/high finding incl. the garbage-parse fallback (`test_narrative.py`).
- LLM router is well-tested for the no-provider terminal path, mode pinning, and empty-text fall-through (`test_llm.py`).
- API tests cover health, catalog, scan, and 422 on invalid mode (`test_api.py`); an opt-in live smoke/regression suite hits a running deployment with cold-start retry and no-secrets assertions (`test_live_smoke.py`).
- **Gaps:** (a) No test exercises the look-alike filter in `ct.py` directly — finding #1 would be caught by a test that feeds `enumerate_live` a mixed list including `evilcorp.com` and asserts it's excluded. (b) `fingerprint.derive_passive` is only exercised indirectly through the mocked scanner test; a direct unit test asserting `CT_SENSITIVE_HOST`/`CT_NONPROD_HOST`/`CT_SURFACE_SPRAWL` classification and apex-skip would lock in live-mode behavior. (c) The mock-signature drift (#4) means the suite would not flag an `enumerate_live` signature change.

## Recommendations (prioritized)
1. **Fix the look-alike domain bug** (`ct.py:40`) — change to `name == domain or name.endswith("." + domain)`, reusing the pattern already correct in `fingerprint.py:39`. Add a direct `ct.enumerate_live` test with a look-alike domain in the input.
2. **Reconcile the stale "no findings" copy** in README (lines 95, 250, 91-94, 59) and `static/index.html:448`, plus the `scanner.py` module docstring, to describe what live mode actually does.
3. **Correct the mock signature** in `test_scanner.py:34-35` to match `enumerate_live(domain, timeout=20.0)`.
4. **Add a direct unit test for `derive_passive`** covering sensitive/non-prod/sprawl classification and apex handling.
5. **Minor:** after #1, re-verify `CT_SURFACE_SPRAWL` counts only in-scope subdomains (`fingerprint.py:62-71`).
