# Code Review: agent-factory

**Health: fair** — The core runtime is well-structured and the test suite is strong, but one confirmed HTTP-500 bug (documented in tests as a known issue), a path-traversal flaw in generated scaffold code, and a ReDoS exposure via the `regex_extract` tool need resolution before the service handles untrusted input at scale.

## Notes

**What is clean:**

- **Calculator sandbox:** The Python and TypeScript calculators both avoid `eval`; the Python version uses a whitelisted AST walk, the TypeScript version a hand-written recursive-descent parser. Both correctly reject attribute access, import calls, and `__dunder__` names.
- **Tool allowlist enforcement:** The planner, `/tool` endpoint, and `execute()` all independently enforce the spec's tool allowlist before any tool is invoked. An out-of-allowlist or unknown tool is refused with a clean `ok=False` observation, never executed, and never causes a 500.
- **Guardrails:** The regex-based injection scanner and PII/secret redactor are deterministic and tested. The `_HARD_BLOCK` set (`jailbreak`, `prompt-exfiltration`) is correctly applied in both `agent.run()` and `orchestrate.run()`.
- **Secrets:** API keys are never echoed in responses. `providers_status()` returns booleans, not key material. The `/providers` test suite plants canary secrets and confirms they don't surface anywhere.
- **LLM fallback chain:** The provider chain always terminates at the deterministic mock; no provider failure can raise from `llm.complete()`. The mock path is tested for reproducibility.
- **Generated scaffold code:** Python scaffold clones the entire runtime (not just a stub) with the package name rewritten, so a generated agent inherits security fixes automatically when regenerated. TypeScript port is a faithful hand-written equivalent.
- **Test coverage:** The test suite covers all major paths — rule planner, LLM planner fallback, guardrail blocking, checkpoint/HITL gate, audit log, zip scaffold, and TypeScript/Python output layout. Security-specific tests confirm no 500 on adversarial input (except the known AF-01 case).

**AF-01 (known bug context):** The `xfail(strict=True)` marker in `test_security.py:159-169` confirms the maintainer is aware of the `OverflowError`. The fix is a one-liner (`except (ToolError, TypeError, OverflowError)`), and the same change is needed in the corresponding `except` clauses in `api.py` and `agent.py`.

**AF-02 scope:** Only affects projects generated by the `/scaffold` endpoint and deployed as standalone services. The `agent-factory` service itself does not expose `thread_id` through its public HTTP API.

**AF-03 exploitability:** Requires `regex_extract` to be in the spec's tool allowlist (it is in the default `assistant` template). A request to `/run` with a pathological regex and a long text string is sufficient to trigger it.
