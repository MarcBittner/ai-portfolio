What counsel is

counsel is a grounded, trust-gated personal-finance copilot. It answers natural-language questions about a synthetic, PII-free account dataset — but it is built so the LLM can never become the source of truth, and so the agent earns trust before it is given any agency.

The trust principles

1
Grounded, or it refuses
Answers come only from retrieved records. Citations are validated against the retrieved set — hallucinated ones are dropped. If a question isn't in your records, counsel says so rather than guessing.
2
Code decides the numbers
Every figure is computed deterministically in Python. The LLM is handed the code-computed facts and asked only to phrase them. The verify panel shows code-computed vs LLM-stated numbers and flags any drift — the model literally can't change a balance.
3
Earn trust before agency
The copilot proposes actions; it never executes. Proposals go to a human-approval queue; only on explicit approval does deterministic code apply — and the apply is simulated, never touching the ground-truth ledger.
4
Safety & bias guardrail
Discriminatory and unlicensed-advice requests are refused deterministically, before any model call — independent of which provider (or no provider) is live.
5
Works with zero keys
A routing chain (paid → local → free → offline) self-selects from the environment. Offline is a deterministic grounded responder — the whole product runs, and the eval reproduces, with no API keys and no cost.

Stack & how the LLM is used

FastAPI + a static SPA · SQLite-free, in-memory deterministic dataset · a vendored multi-provider llm.py router (Anthropic / OpenAI → Ollama → OpenRouter → deterministic offline). The LLM's only job is narration: it receives code-computed facts + the allowed record ids and returns a sentence plus citations. It is never asked for a number, never executes an action, and is gated by a deterministic guardrail.

Help · counsel

What it is

counsel answers natural-language questions about a finance account dataset — but the LLM never owns a number. Deterministic code computes every figure, validates the model's citations against the retrieved records, and verifies its stated numbers (if they disagree, the code value wins). Unsafe or ungrounded asks are refused. Actions are only proposed, and applied solely after a human approves — and even then the apply is simulated, so the ground-truth ledger is never mutated.

How to use

  1. Ask — on the Copilot tab, pick an example chip or type a question, then review the answer's citations and the verify panel (code-computed vs LLM-stated).
  2. See the guardrails — try an ungrounded ask (What's my credit score?) and a guarded one (Which stock should I buy?) to watch counsel refuse honestly.
  3. Propose & approve — on Approvals, propose an action and approve or decline it; nothing changes until you approve, and the effect is simulated.
  4. Compare modes — on Diagnostics, run the cross-routing-mode benchmark to see grounding, verification, and refusals hold across every routing tier.

Trust model

The model reads and phrases; code decides every number and safety call; a human approves every action.

All data is a synthetic, PII-free sample ledger generated in code — no real person and no real balances.
