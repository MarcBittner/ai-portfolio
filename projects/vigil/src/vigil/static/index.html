Synthetic checks — the definition of "up"

A target is up when all its required checks pass. Each check is an HTTP request (method + path + headers + optional body) plus an assertion set: status range/equality, latency budget, body-contains/regex, JSON-path equals/exists/lt/gt/contains, and header equals/exists/contains. The seeded health check (GET the health path, status 200–399) preserves the original behavior. Admin only.

About vigil what it is · how it works · how the model is used

vigil is a public observability + SOC monitor for a whole fleet of apps — and for itself. On a schedule it probes each app's health URL, records a time series, and derives rolling uptime, error rate, and latency. It scores each app's security & compliance posture from live endpoint checks, turning them into risk-qualified findings mapped to real controls across SOC 2, HIPAA, ISO 27001, NIST 800-53, NIST 800-171, and CMMC. It dispatches configurable alerts when a target degrades, and compresses the live fleet state into an LLM-written incident narrative. What you can see is tiered and enforced server-side: guests see live status, registered users get history + the incident AI, elevated users see the compliance posture, and an admin manages the registry and roles.

The principle
  • ▸The LLM reads, the code decides. Status, severity, the posture score, and alert thresholds are all computed in deterministic Python — the model only narrates the result.
  • ▸Every compliance finding is risk-qualified and mapped to at least one control, then crosswalked across six frameworks and rolled into a single severity-weighted grade.
  • ▸Tiering is enforced server-side, not by hiding buttons — each endpoint checks the caller's role and returns 401/403.
  • ▸Runs fully offline with zero keys: no model, no SMTP, no OAuth required — each integration switches on only when its credential is set, and degrades gracefully until then.
How the model is used

There's one genuine LLM surface: the incident / fleet-health summarizer. It reads the live fleet state and writes a concise status narrative plus prioritized actions. Code decides the severity and the impacted priority order from the metrics — never the model.

Summaries are generated server-side through a vendored stdlib router that tries providers in order — paid (Anthropic / OpenAI) → local (Ollama) → free (OpenRouter) → a deterministic offline drafter. The offline drafter emits the same JSON shape, so the feature reproduces end-to-end with no keys at all.
